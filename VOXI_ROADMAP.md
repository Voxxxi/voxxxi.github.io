# VOXi — согласованные следующие этапы

Обновлено: 19 октября 2026 г.

## 1. Регистрация клиента
Google-вход → обязательные отдельные поля «Имя», «Фамилия», «Телефон» → сохранение профиля → кабинет или продолжение записи.
В существующей базе имя и фамилия хранятся в voxi_profiles.full_name; телефон нормализуется; аккаунт определяется user_id. Анкета появляется автоматически при неполном профиле, повторно полным профилям не показывается.

Регистрация проверена пользователем на сайте: обязательная анкета сразу после Google-входа появляется и работает.

## 2. Управление пользователями в админке
- Отдельная кнопка «Пользователи»: список аккаунтов с именем, фамилией, телефоном и user_id, поиск по этим полям.
- Показывать и аккаунты без заполненного профиля: источник полного списка — Supabase Auth, не только voxi_profiles.
- Удаление выбранного аккаунта с понятным подтверждением конкретного имени/ID. Два тестовых аккаунта пользователь удалит сам после появления функции; произвольные аккаунты автоматически не удалять.
- Владелец может назначать доверенным помощникам роли. Разделить «помощник» (заявки/контент) и «администратор»; управление ролями и удаление аккаунтов оставить владельцу.
- Проверять права на сервере и в RLS. Роль, которую клиент сам может записать в профиль или user_metadata, не даёт полномочий.
- Supabase Auth Admin API вызывается только сервером. service_role/секретные ключи запрещены в HTML/JS и публичном репозитории.
- Защитить владельца от удаления/понижения роли. Учесть связанные файлы и данные, отзыв сессий и срок жизни JWT. Не обещать мгновенное прекращение доступа без серверной проверки состояния аккаунта.
- Перед изменением backend проверить реальную схему/внешние ключи/RLS; удаление только строки профиля не является удалением учётной записи.
Статус: требования записаны; список, удаление и роли ещё не реализованы. Supabase подключён, но список проектов пуст; запрос к проекту сайта vnykpjarjvacwhxvkxrk возвращает отказ в доступе. Видна организация VOXi. Для работы требуется доступ подключения именно к существующему проекту; новый проект вместо него не создавать.

## 3. «Мои клиенты» и выдача готовых песен
Администратор должен находить клиента по номеру телефона, имени или фамилии, выбирать конкретный аккаунт и загружать ему записанную песню.
Поиск — средство найти аккаунт; владелец файла — выбранный user_id. Совпадение имени/номера само по себе не даёт права на архивные песни.
Нужны проверка реальной схемы voxi_tracks, RLS для администратора/владельца и безопасный доступ к приватному bucket voxi-tracks. Загрузку файлов пользователь ещё не настраивал.
Не объявлять медиатеку работающей до настройки backend и проверки реальных файлов.

## 4. Видео клиентов с праздников
Согласованный сценарий:
- В разделе «Мои видео» сам клиент загружает видео со своего телефона, например выступление с песней на дне рождения мамы.
- Одобренные клиентские ролики доступны для просмотра всем желающим, включая посетителей без входа.
- На главной сразу ПОД существующим музыкальным плеером появляется видеоплеер.
- Внешний вид видеоплеера соответствует музыкальному: тот же чёрно-золотой стиль, шрифты, размеры и общий характер оформления.
- Ролики разных клиентов и разных праздников показываются в случайном порядке.
- Цель — показать реальные выступления клиентов и рекламировать студию.
- В загрузке должно быть понятно, что одобренный ролик появится в публичной ленте.

### Защита загрузки и проверка содержания
Пользователь отдельно потребовал капчу ИМЕННО при загрузке клиентского видео в «Мои видео», а не на просмотре, не при входе и не по всему сайту.
- Предпочтительный вариант: Cloudflare Turnstile в форме загрузки. Перед выдачей разрешения на загрузку сервер проверяет текущего пользователя и токен через Siteverify; проверяет success, hostname и action, истечение/повторное использование токена. Ошибка или недоступность проверки не разрешает новую загрузку. Секрет Turnstile хранится только на сервере.
- Одной проверки в браузере недостаточно. Прямая запись клиента в хранилище должна быть запрещена; после проверки сервер выдаёт ограниченное разрешение на один путь/один файл выбранного пользователя. Токен капчи не нужно держать действительным во время долгой передачи файла.
- Капча уменьшает автоматические загрузки, но не проверяет содержание и не исключает всех ботов. Дополнить серверными лимитами частоты/объёма на пользователя и ограничениями файла.
- Файл сначала попадает в приватное хранилище на проверку. До одобрения его могут смотреть только автор и уполномоченный модератор через защищённый доступ. Не хранить ожидающие/отклонённые видео в открытом bucket даже при скрытой карточке.
- Начальный порядок публикации: загружено → «На проверке» → владелец/модератор смотрит → «Опубликовано» или «Отклонено» с причиной для автора. Это предложенный безопасный порядок; пользователь пока не подтверждал отдельную автоматическую публикацию.
- Только серверная роль модератора меняет статус публикации. Автор не может назначить себе approved или подменить владельца файла.
- Автоматический анализ нежелательных сцен возможен отдельным сервисом; он ещё не подключён и не гарантирует отсутствие нарушений. Не заявлять проверку ИИ работающей. Если подключим, результат дополняет модерацию; при сбое анализа автоматической публикации нет.
- Сервер проверяет реальный тип/целостность файла, размер и длительность; окончательные лимиты выбрать перед реализацией. Непрошедшие/брошенные загрузки удалять по правилам хранения.
- Возможность пожаловаться на опубликованный ролик и быстро скрыть его из ленты.

### Уведомление о новом видео
Пользователь запросил уведомление в Telegram ИЛИ в админке при загрузке видео.
Базовый вариант — уведомление в админке: автор, время, название/ID ролика, статус «На проверке» и переход к просмотру/одобрению/отклонению.
Создавать уведомление только после подтверждённого завершения загрузки, не при выборе файла. Повторный callback не создаёт дубликат. Ошибка доставки не публикует видео и не теряет запись очереди проверки.
Дополнительно можно подключить Telegram-бота для владельца. Bot token — только серверный секрет; получатель подтверждается владельцем. Не включать публичную ссылку на приватное видео; сообщение ведёт к защищённой админке. Отправка владельцу разрешена этим запросом, сторонним получателям без указания пользователя не отправлять.
Статус: требования сохранены, уведомления ещё не реализованы.

Проверка перед запуском: без входа/без капчи/с поддельным, просроченным или повторным токеном загрузка не разрешается; прямой обход хранилища запрещён; чужие ожидающие файлы недоступны; в публичной ленте только одобренное; автор не меняет статус; превышение лимита и ошибки сервиса объясняются пользователю без публикации.
Это отдельный публичный видеопоток; доступ к приватным студийным песням от него не меняется.
Пока записаны требования. Backend, загрузка и плеер этого этапа ещё не реализованы.
